### Issues
#### Critical (Must Fix)
None.

#### Important (Should Fix)
1. `RunBroker_SessionFails_FlushesDiagnosticsBeforeLeaving` (`DefaultElevatedEntryRunnerTests.cs:190-233`) is the one runner test the hazard fix does not cover. It starts the runner with `Task.Run(...)` and never routes through `EnsureRunnerLeavesAsync`, so `_runnerStillServing` can never be set for it. If any bounded wait before the final `runTask.WaitAsync` times out (`server.WaitForConnectionAsync` at :212, `sink.Entered` :217, `FlushBoundStarted` :218), `await using` disposes `server`, the test method exits, `[TestCleanup]` runs `DefaultElevatedEntryRunner.ResetToDefaults()` (real `Environment.Exit`), and the still-serving runner thread reaches its exit path against the real seam and can kill the test host. That is exactly the hazard the ruling asked to close ("a runner test that times out must not let cleanup restore the real Environment.Exit while an orphaned RunBroker thread is still serving"). The success path is safe (the runner throws, exit is not called, `Assert.IsNull(exitCode)`), so this only bites on failure, which is when a clear failure matters. Fix: wrap the body in try/finally that calls `EnsureRunnerLeavesAsync(runTask, server)` (release `sink` first so the flush wait can end).
