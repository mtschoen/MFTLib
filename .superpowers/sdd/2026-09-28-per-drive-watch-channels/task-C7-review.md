### Issues

#### Critical (Must Fix)

None.

#### Important (Should Fix)

1. **A frame arriving as the stall timer fires can permanently disable stall detection.** `CheckStall` sets `_stalled = true` before cancelling the read (`MFTLib/Broker/Client/BrokerFrameReader.cs:132-137`). If the frame read has completed concurrently, the normal return at lines 56-57 can win; `EndRead` then clears only `_reading` (`:105-110`). `_stalled` remains true, so every later timer callback exits at lines 127-129 and a subsequent silent read can wait forever. The reader needs a per-read identity/completion handshake so exactly one of frame completion or stall wins and the state cannot poison later reads. Add a deterministic race regression test, since the current fake-clock tests serialize frame delivery and timer firing.

2. **Reader disposal does not ensure the timer callback has drained.** `BrokerFrameReader.Dispose` calls only synchronous `ITimer.Dispose()` and returns (`MFTLib/Broker/Client/BrokerFrameReader.cs:81-88`). That prevents future scheduling but does not wait for a callback already queued or executing, and the callback captures the reader and its stream (`:99`, `:123-142`). `BrokerDriveChannel.DisposeAsync` can therefore finish after closing the pipe while `CheckStall` is still running (`MFTLib/Broker/Client/BrokerDriveChannel.cs:89-99`), contrary to the required timer lifetime. Make reader teardown asynchronous and await `ITimer.DisposeAsync()` before channel/process teardown completes; test with a callback gate that proves disposal waits for the callback.

3. **The new tests can hang instead of failing their hang guard.** Top-level tests await `StartScanAsync`, writes, and request reads without `WaitAsync(HangGuard)` (`MFTLib.Tests/BrokerProcessLivenessTests.cs:79-87`, `:112-122`, `:185`, `:211`). The helper compounds this with unbounded `ReadRequestAsync`, `ConnectAsync(..., CancellationToken.None)`, and `ReadFrameAsync` calls (`:298-319`); `ScriptedBroker.ReadRequestAsync` itself is a raw frame read with no bound (`MFTLib.Tests/TestSupport/ScriptedBroker.cs:32-35`). This violates the inherited rule that every test await is bounded and turns the failure modes these tests exercise into suite hangs. Bound each externally progressing helper/task, including helper internals, with `HangGuard`.

#### Minor (Nice to Have)

1. **`ScanDriveAsync` does not document its new reply-timeout exception.** Its volume query and `OpenChannel` request can now throw `TimeoutException` (`MFTLib/Broker/Client/BrokerProcess.Scan.cs:29`, `:51-52`), but the public XML contract lists only `InvalidOperationException` and `BrokerChannelLostException` (`:18-20`). Add the same timeout exception entry already present on the two direct control APIs (`MFTLib/Broker/Client/BrokerProcess.Control.cs:52`, `:71`).
