### Issues

#### Important (Should Fix)

- `WatchFaulted` uses one delivery marker for the entire multicast delegate, not one marker per handler invocation. `Deliver(subscribers, fault)` at `MFTLib/Index/FileIndex.WatchPump.cs:232` keeps the marker active after subscriber A returns while subscriber B is still running. Work A queued to run after A returned can therefore be rejected even though the required remedy says it is allowed. It also contradicts `Deliver`'s own exactly-one-invocation contract at `MFTLib/Index/FileIndex.Reentrancy.cs:18`. Enumerate the invocation list and scope a fresh marker around each subscriber, with a regression where A queues lifecycle work and B remains gated.

- Nested delivery on another index hides an outer active marker and can restore the deadlock the guard exists to prevent. `Deliver` replaces the sole AsyncLocal value at `MFTLib/Index/FileIndex.Reentrancy.cs:21-23`, while the rejection checks only that current value at `MFTLib/Index/FileIndex.Reentrancy.cs:41`. If index A's handler synchronously raises a callback on index B, and B's handler blocks on a lifecycle call on A, the active A marker is hidden by B's marker and A does not reject the call even though A's pump is still blocked in its handler. Preserve and search an active marker chain, or otherwise keep per-index active delivery state in the execution context, and add this cross-index nesting regression.

- The batched public entry paths do not always return the required callback exception. The no-list overloads call `AllDriveLetters()` before reaching the list overload's guard (`MFTLib/Index/FileIndex.Batched.cs:26-28`, `MFTLib/Index/FileIndex.Batched.cs:45-47`, `MFTLib/Index/FileIndex.Batched.cs:64-66`, `MFTLib/Index/FileIndex.Batched.cs:95-97`), and `AllDriveLetters` throws `ObjectDisposedException` at `MFTLib/Index/FileIndex.Batched.cs:121-124`. Thus a callback still running while concurrent disposal has marked the index disposed gets a synchronous wrong exception instead of the already-faulted task with the verbatim guard message. In addition, a list catch-up call with an already-cancelled token and a pending drive is rejected at `MFTLib/Index/FileIndex.Batched.cs:85-89`, whereas the equivalent single-drive call returns an already-settled cancelled task at `MFTLib/Index/FileIndex.WatchCatchUp.cs:76-79`. Guard every no-list form at its own entry, and treat an already-cancelled batched wait as settled.

- The new tests violate the binding rule that every await, including helpers, be bounded. `StartBothAsync` directly awaits both public starts without a timeout (`MFTLib.Tests/Index/FileIndexCallbackReentrancyTests.cs:449-452`) and is itself awaited without a bound throughout the class, beginning at `MFTLib.Tests/Index/FileIndexCallbackReentrancyTests.cs:36`; the single start at `MFTLib.Tests/Index/FileIndexCallbackReentrancyTests.cs:133` is also unbounded. A start-path regression can therefore hang the suite instead of producing the required bounded failure. Apply the existing HangGuard to those starts and to the helper boundary.
