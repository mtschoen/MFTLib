# Task C7 report: client liveness

Status: DONE_WITH_CONCERNS. Commit b7e1144 "BrokerProcess closes any pipe that goes silent past the stall limit" on task/265-C7 (base e44243c verified).

## Implemented
- `BrokerFrameReader` (now IDisposable, takes a TimeProvider): one timer per reader, armed for StallLimit, re-arming for the remainder each time it fires without the limit having passed since the current read began (a frame costs a timestamp, not a timer; the clock starts at read start so consumer time away is not host silence). On stall: cancels the read, disposes the stream (host reads EOF), throws `BrokerChannelLostException(drive, "No frame from the broker for 30 seconds", inner TimeoutException)`. The inner exception is neither OperationCanceledException nor ObjectDisposedException and the channel's `_closing` is not set, so `IsOwnClose` is false: a stall can never be mistaken for own close.
- `BrokerDriveChannel`: takes the TimeProvider, disposes its reader; converts a `Stalled` frame into `BrokerChannelLostException(drive, hostMessage)` (in the channel read, not in ScanFrames, which keeps ScanFrames under aislop's 80-line limit and serves later watch channels).
- `BrokerProcess.Control.cs`: control reader uses the same limit (stall ends the process, `Ended` fires with the stall message); `RequestAsync` waits `ControlReplyTimeout` for the reply on the injected clock, throws `TimeoutException`, leaves the pending entry for the late reply to drop. `BrokerProcess.cs` doc, `Channels.cs` passes the clock.
- C2's two limits (started control write, acknowledged-but-unconnected channel) untouched.
