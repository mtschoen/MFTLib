### Suspected Production Defect

Important - confirmed real production defect. `ScanDriveAsync` releases the section lifetime immediately after consuming `ScanReady` (`MFTLib/Broker/Client/BrokerProcess.Scan.cs:55-61`). If terminal-frame processing then throws, the broad catch releases the same lifetime again before disposing the block (`MFTLib/Broker/Client/BrokerProcess.Scan.cs:68-73`). This deterministically explains the reported count of 2 for disconnection, repeated-ready, and error-after-ready paths. The production file is unchanged from fix base 1dd2425, so the test-only fix diff exposed rather than introduced the defect.

The exact-one-dispose assertion is the right contract. The section-factory contract says the scan disposes the lifetime once after the section is written (`MFTLib/Broker/Client/BrokerBlockSectionFactory.cs:5-10`). The design requires an error after `ScanReady` to fail the scan, dispose the section, and return no block (`docs/superpowers/specs/2026-09-28-per-drive-watch-channels-design.md:307-317`); once the lifetime was released at `ScanReady`, that obligation is already satisfied and the later failure only needs to dispose the block. The base client also enforced single ownership transfer by removing the lifetime when taking it (`c1d43784:MFTLib/Broker/Client/JournalBrokerClient.Scan.cs:84-89`) and therefore made later cleanup a no-op after the `ScanReady` release (`c1d43784:MFTLib/Broker/Client/JournalBrokerClient.ScanCollector.cs:91-107`). The real `MemoryMappedFile` happens to tolerate repeat disposal, but the injected `IDisposable` factory contract does not promise idempotence.

The smallest correct production fix is to represent local ownership explicitly and release it through one release-once helper at both current call sites. The helper must mark the lifetime released before invoking `Dispose`, so an exception from `Dispose` cannot cause the catch to invoke it again. Before `ScanReady`, the catch releases the lifetime and block; after `ScanReady`, it skips the already-released lifetime and disposes only the block. No protocol or producer change is needed.
