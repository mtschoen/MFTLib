#### Important (Should Fix)
1. **A stop can be lost while recovery registers its restarted watch.** `RestartRequestedWatchAsync` reads `runtime.WatchRequested` under `_stateLock` and then releases the lock before calling the restart (`MFTLib/Index/FileIndex.RescanRestart.cs:169`). `StopWatchingAsync` deliberately takes no lifecycle gate, clears `WatchRequested` and the ticket, and can return during this interval (`MFTLib/Index/FileIndex.WatchDrive.cs:58`). The recovery path does not revalidate either value before registration, and `RegisterStartingInstance` unconditionally writes `runtime.WatchRequested = true` (`MFTLib/Index/FileIndex.WatchDrive.cs:214`). Therefore a stop after the restart decision but before registration is overwritten by the recovery, which starts a new watch after the stop returned. This violates the binding rule that a recovery already past revalidation may commit but must not restart after stop. The existing test stops while production is held, before the restart decision, so it cannot catch this interleaving (`MFTLib.Tests/Index/FileIndexWatchRecoveryTests.cs:153`). Recheck the request and ticket atomically at recovery registration, and add a `TestGate` at that boundary.

2. **Plan-mandated RED evidence omits the exact command for two new tests.** `QueuedRecovery_SupersededByConsumerStart_DoesNotScan` and `StopBetweenFaultAndQueue_QueuesNoRecovery` were added after the initial 21-test RED run (`MFTLib.Tests/Index/FileIndexWatchRecoveryTests.cs:294`, `MFTLib.Tests/Index/FileIndexWatchRecoveryTests.cs:320`).
